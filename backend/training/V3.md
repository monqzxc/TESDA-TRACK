# Train TESDA-TRACK v3 in Google Colab

Open **[train_colab_v3.ipynb](colab/train_colab_v3.ipynb)** using Colab's **File → Upload notebook**,
choose a T4 GPU runtime, then run the cells in order. Upload `training/runs/colab-bundle-v3.zip`
when prompted. First run with `SMOKE = True`; after it passes, set `SMOKE = False` and rerun from Settings.
The full run downloads `tesda-e5-small-v3.zip` and also saves it to Drive when enabled.

This is a training recipe and dataset, not already-trained v3 weights. It starts from
`intfloat/multilingual-e5-small`; v2's serving-only ONNX archive is not used as a trainable checkpoint.
The existing v2 notebook remains available. Neither creating the bundle nor running this notebook changes the live app.

## Added capabilities

| Addition | What it supplies |
| --- | --- |
| Cebuano/Bisaya, Ilocano, Hiligaynon/Ilonggo | 1,179 labeled examples per language: code-switched job requests plus 15 manually authored synthetic task requests |
| Qualification depth | Core-task queries, paired skills, and requests naming the qualification's exact NC level across the 319-entry committed catalog |
| Coverage audit | JSON counts per language, example kind and qualification, plus qualifications missing Core units |
| Validation | Normalized query groups stay in one loss split; all evaluation goals are excluded before training/augmentation |
| Safer negatives | Other accepted owners and ambiguous sibling levels cannot become mined or random negatives |
| Colab recovery | Two recent checkpoints, saved every 100 steps; resume checks data and settings fingerprints |
| Serving checks | ONNX parity, separate smoke/full outputs, checksummed downloads, and a qualification-detail retrieval preview |
| Evaluation reporting | Top-1, top-3, MRR, rejection and sample counts per language in the JSON report |

The generated dataset currently has **40,356 training pairs**, including augmentation and older training examples.
Counts can change as the catalog or data changes. Run the audit below to obtain current counts.

## What the data does and does not establish

`data/v3/regional_tasks.json` contains synthetic language drafts, **not native-speaker-reviewed translations**.
Most new regional examples deliberately retain English job titles. The additional 21 dev and 15 sealed goals
are small synthetic regression sets, not representative language benchmarks. Review and expand them with native
speakers before claiming reliable regional-language performance; inspect each language's sample counts and errors.
Existing English, Filipino and Taglish examples are retained.

Qualification content comes from the committed `seed/qualifications.json`, derived from TESDA Training Regulations.
No new qualifications, admission requirements, fees, training hours or certification equivalencies are invented.
The deeper examples cover **existing Section 1 Core-unit titles**, not new extraction of performance criteria
from the full regulations. Shared generic Core units are excluded as standalone task examples when more than three
qualifications own them. Explicit level examples name the actual qualification; multi-skill examples combine its
first and last Core unit. All positive passages retain the API's existing format and 384-dimensional embeddings.
The preview lists jobs and Core units, but neither it nor embedding similarity assesses learner readiness.

## Rebuild the bundle locally

From the repository root in PowerShell (no GPU or database required):

```powershell
Set-Location backend
../.venv/Scripts/python -m training.v3 --output training/runs/v3-coverage.json
../.venv/Scripts/python -m training.bundle --output training/runs/colab-bundle-v3.zip
```

The bundle includes public catalog text, training code, synthetic examples, a checksum manifest and evaluation
exclusion hashes. It excludes evaluation goal files, learner records, `.env`, models and credentials.
In Colab, dependency failures stop execution, GPU availability is checked, and the bundle checksums are verified.
GPU resources are not guaranteed; see [Colab's FAQ](https://research.google.com/colaboratory/faq.html).
E5's input prefixes and length limit follow its [model card](https://huggingface.co/intfloat/multilingual-e5-small).

Optional harder examples: mine fresh negatives from v2 using the same v3 profile, then rebuild the bundle:

```powershell
../.venv/Scripts/python -m training.mine --profile v3 --model-path models/tesda-e5-small-v2 --output training/runs/hard-negatives-v3-regional.json --k 3
../.venv/Scripts/python -m training.bundle --output training/runs/colab-bundle-v3.zip --hard-negatives training/runs/hard-negatives-v3-regional.json
```

Set `HARD_NEGATIVES = True` and `NEGATIVE_FILE = "hard-negatives-v3-regional.json"` in the notebook.
The default bundle works without mining, using in-batch negatives. Do not silently reuse old negative files;
new v3 queries would otherwise receive random rather than mined negatives.

## Evaluate the trained download

Extract the archive into a new `backend/models/tesda-e5-small-v3/` folder. From `backend/`:

```powershell
# Compare dev performance with v2, using the same expanded goal set.
../.venv/Scripts/python -m training.evaluate --model-path models/tesda-e5-small-v2 --set dev --json training/runs/v2-regional-dev.json
../.venv/Scripts/python -m training.evaluate --model-path models/tesda-e5-small-v3 --set dev --calibrate --min-rejection 0.9 --json training/runs/v3-dev.json
```

Review `metrics.dev.language_details`, scenario tags and `errors` in `v3-dev.json` before proceeding.
Calibration prints parameters but does not automatically save them into the serving folder. After accepting the
dev results, save its parameters (this command refuses a report below the requested rejection floor):

```powershell
../.venv/Scripts/python -c "import json; from pathlib import Path; r=json.loads(Path('training/runs/v3-dev.json').read_text()); assert r['model']=='tesda-track/tesda-e5-small-v3'; assert r['metrics']['dev']['rejection'] >= 0.9; Path('models/tesda-e5-small-v3/calibration.json').write_text(json.dumps(r['params'], indent=2))"
../.venv/Scripts/python -m training.evaluate --model-path models/tesda-e5-small-v3 --set test_v1 --json training/runs/v3-test-v1.json
../.venv/Scripts/python -m training.evaluate --model-path models/tesda-e5-small-v3 --set sealed --final --json training/runs/v3-final.json
```

Use the sealed set once per final candidate; do not tune to its results. Inspect rejection per language as well
as the overall result: the small regional sets cannot establish a robust rejection threshold by themselves.
Lower held-out training loss or a passing export check alone does not show retrieval improvement.

Only after approving the evaluation, configure the app with a new model identity:

```dotenv
EMBEDDING_MODEL=tesda-track/tesda-e5-small-v3
EMBEDDING_MODEL_PATH=backend/models/tesda-e5-small-v3
```

Run `python -m tesda_track.embeddings sync` from `backend/` and restart the API. Docker uses
`EMBEDDING_MODEL_PATH=/app/finetuned/tesda-e5-small-v3` and requires an image rebuild. See
`../models/README.md` for deployment details. Keep v2's model folder and calibration for rollback.

## Verification

From the repository root, run the database-free training tests:

```powershell
.venv/Scripts/python -m pytest --confcutdir=backend/tests --basetemp=backend/training/runs/pytest-v3 backend/tests/test_training_v3.py backend/tests/test_training_bundle.py backend/tests/test_training_finetune.py backend/tests/test_training_goals.py backend/tests/test_training_pairs.py backend/tests/test_training_evaluate.py backend/tests/test_training_eval_goals.py backend/tests/test_training_mine.py
```

These validate data, exclusion boundaries, negative selection, grouped splitting, metrics, bundling and notebook
syntax. Actual GPU training, CUDA memory usage and ONNX parity must be exercised with the Colab smoke run.
